# PL Creators Suite v1.1 Recovery Baseline

## Purpose

This document records the recovery and corruption-handling behavior validated during Wave 1.1.5.

Wave 1.1 establishes a safety baseline. It does not claim completion of the later shared autosave, snapshot, history, and crash-recovery platform.

## Validated Failure Behavior

The v1.1 baseline verifies that:

- projects missing their manifest fail visibly
- corrupt manifest JSON is rejected
- projects from unsupported future schema versions are rejected
- project checksum validation detects modified manifests
- integrity inspection reports damaged project state
- protected manifest rewrites can preserve a backup
- repair entry points can restore a manifest backup
- invalid project imports do not install incomplete projects
- failed imports clean staging directories
- future-schema imports fail without leaving partial installed projects

## Existing Recovery Infrastructure

Current project persistence includes:

- atomic manifest replacement
- optional pre-rewrite manifest backups
- schema validation
- future-version rejection
- checksum manifests
- integrity inspection
- project journals
- repair entry points
- staged project imports
- failed-import cleanup

## Known v1.1 Limits

The following are outside the v1.1 recovery baseline:

- continuous autosave
- periodic project snapshots
- general undo-history persistence
- automatic session crash restoration
- worker restart supervision
- engine process restart
- transactional rollback for every slice mutation
- complete third-party extension crash containment

Those capabilities belong to later shared-platform and engine work.

## Interpretation

A passing v1.1 recovery baseline means currently implemented project persistence and import boundaries reject the tested corruption cases safely and preserve the recovery mechanisms that already exist.

It does not mean every future failure mode is automatically recoverable.
