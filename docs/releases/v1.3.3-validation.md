## Diagnostic Export Schema

Schema version: 1

Package kind:

pl-diagnostic-export

Format: JSON

The export contains:

- Schema identification
- Generation timestamp
- Privacy metadata
- Safe project-open state
- Minimized health information
- Selected operational diagnostic metadata

Excluded data:

- Raw source code
- Document contents
- Spreadsheet contents
- Media and project assets
- AI prompts and responses
- Credentials and session tokens
- Arbitrary diagnostic details
- Raw project paths

Diagnostic exports are static local artifacts.

They are not automatically uploaded, transmitted,
or imported into the live diagnostic store.

No new diagnostic import mechanism is introduced.

## Failure Isolation

Existing HealthService behavior catches individual
collector exceptions and represents them as
unavailable health sources.

Validation must establish:

- Healthy collectors continue after another fails
- Failed collectors report unavailable
- The snapshot retains failure findings
- Diagnostic export excludes raw collector errors
- Health Center remains usable

Known limitation:

Individual collector timeouts are not yet enforced.
A collector that never settles may delay the
aggregated snapshot.

This limitation requires release-gate review.

---

## Privacy and Security

Diagnostic export is explicitly user-initiated.

It does not create a network transmission.

The export method requires filesystem.write
authorization through the existing RPC contract.

The package minimizes exported operational data.

Export does not alter diagnostic history.

Additional validation must cover:

- Invalid output paths
- Existing destination files
- Unexpected symbolic links
- Partial-write cleanup
- Malformed diagnostic records
- Sensitive-value fixtures
- Permission-denied behavior

---

## Migration and Compatibility

The exported diagnostic format begins at schema v1.

No existing persisted diagnostic data is migrated
by this feature.

No automatic import or reverse migration exists.

Existing logs.export behavior remains unchanged.

Future schema versions must be explicitly
recognized before they are supported.
