# PL Creators Suite v1.2.3 Validation

## Wave

v1.2.3 — Project, Asset, Indexing, and Global Search Services

## Objective

Provide shared project, asset, dependency, indexing, search, reference,
and cache ownership infrastructure without duplicating existing project
persistence.

## Implemented

### Project Services

- Shared project metadata contract
- Shared recent-project contract
- Shared project tree contract
- Desktop project metadata bridge
- Existing recents persistence reused
- Recursive project tree inspection
- Project-root path containment

### Asset Services

- Typed asset records
- Asset kind and resource-state contracts
- Source and derived ownership
- Asset references
- Dependency graph
- Forward dependency traversal
- Reverse dependent traversal
- Missing-asset detection
- Safe replacement repair
- Project-internal relinking
- Compatibility adapter for existing asset-registry.json format

Existing project asset registries are not silently migrated or rewritten
into a new schema by the platform bridge.

### Indexing

- Project-local `.pl-index/project-index.json`
- Atomic index writes
- SHA-256 streamed content hashing
- Incremental file scanning
- Added, changed, unchanged, and removed classification
- Metadata-based stale detection
- Changed-file-only rehashing
- Index status reporting
- Progress callbacks
- Cooperative cancellation
- Lightweight project indexing job state
- Index directory self-exclusion

### Global Search

Search result contracts support:

- files
- documents
- cells
- symbols
- assets
- scenes
- shots
- tasks
- workflows
- extension content

Current baseline search includes:

- indexed file-name search
- indexed text-content search
- line and column navigation
- result previews
- result-kind filtering
- asset registry search
- result limits
- cooperative cancellation
- provider-based shared search contracts for later richer slice/engine providers

Current classification of document, cell, symbol, scene, shot, task,
workflow, and extension content is a baseline path/file-type adapter.
Later specialized engines may contribute richer semantic providers
without replacing the global search contract.

### Cache Ownership

- Source and derived ownership are distinct from resource state.
- Dependency traversal identifies derived dependents.
- Only derived assets are automatically eligible for stale marking.
- Source assets remain authoritative.
- Cache invalidation returns explicit affected asset IDs.

## Existing Storage Compatibility

The wave builds around the existing:

- project manifest persistence
- recent-project persistence
- asset-registry.json persistence
- atomic project data contracts

No second authoritative project or asset database is introduced.

## Deferred

Not part of v1.2.3:

- language-server semantic symbol indexing
- spreadsheet-engine formula/cell semantic index
- scene-engine semantic object index
- worker-thread/process execution
- distributed indexing
- cloud search
- collaboration search
- generalized task queue
- full extension runtime search providers

Those integrate through the contracts established here in later roadmap
waves.

## Status

PASS — v1.2.3 project, asset, indexing, and global search services validated.
